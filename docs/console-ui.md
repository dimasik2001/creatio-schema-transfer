## 1. Общее

- Библиотека: **Spectre.Console** (netstandard2.0) — в обеих сборках: `cst.exe` (net10.0) и `cst.dll` (net48, PowerShell-кит).
  В кит `transfer\cst-ps\` добавляется `Spectre.Console.dll` (и её зависимости, если появятся).
- UI запускается, когда cst вызван **без параметров** и консоль интерактивна (`!Console.IsInputRedirected`
  и `!Console.IsOutputRedirected`). Иначе — как сейчас: help и код 1. В PowerShell ISE и других хостах без
  настоящей консоли UI не работает — это осознанное ограничение; там остаётся обычный CLI.
- Все существующие команды CLI не меняются; UI — надстройка над теми же классами (`Catalog`, `Exporter`,
  `Importer`, `SchemaList`, `Manifest`, `FileTransfer`), без вызова cst как внешнего процесса.
- Главное меню: **Export · Import · Restore · Language · Quit**.

### Язык интерфейса (2026-11-20)

- Английский (по умолчанию) или украинский: пункт **Language / Мова** в главном меню; выбор запоминается в
  `cst.ui-state.json` (`"Language": "en" | "uk"`).
- Переводится только UI: меню, заголовки, подсказки клавиш, таблицы, вопросы, названия папок элементов и этапов.
  Сообщения самого cst (лог, проверки, ошибки Creatio, план dry-run, `.missing.md`) и текст сохраняемого списка
  остаются английскими, как в CLI.
- Тексты: `src\Cst\Ui\Lang.cs` (`T(english)`, `F(englishFormat, …)`; ключ — английский текст, без перевода
  показывается английский) и `Lang.uk.cs` (словарь). `tests\ui-lang-check.ps1` показывает тексты без перевода
  и неиспользуемые переводы (код 1, если перевода нет).
- Вопросы y/N читаются по клавишам (Y/N, затем Enter), а не по символам — работают и в украинской раскладке.

### Настройки и стенды

- appsettings.json читается так же, как в CLI (рядом с exe/dll).
- Пароль: `Password` → `CST_PASSWORD_<ENV>` → `CST_PASSWORD` → скрытый ввод при первом обращении к стенду.
  Введённый пароль живёт только в памяти до конца сессии; не пишется ни в appsettings, ни в state, ни в лог.
- Неверный пароль (401): повторный ввод без лимита, выход по `Esc` (к выбору стенда). После второй неудачи —
  предупреждение `Creatio may lock the user after several failed logins`. Если стенд ответил, что пользователь
  заблокирован, — прямое сообщение, без повтора.
- Сразу после выбора стенда — проверка подключения (логин + `GetAppInfoAsync`); шапка экрана показывает
  `<env> · <core version> · <DbEngine>`. Ошибка подключения видна до начала выбора.

### Состояние между запусками — `cst.ui-state.json`

Рядом с appsettings. Без паролей. Содержит:
- маппинг пакетов для пары стендов (`dev→test: { "UtkIntegration": "UtkIntegrationTest" }`);
- последние исходный и целевой стенды;
- последние списки, архивы, work dir (для Import и Restore), ~10 каждого.

Повреждён или недоступен — UI работает как при первом запуске (и пишет предупреждение один раз).
Запомненный маппинг подставляется автоматически с пометкой `(remembered)`.

### Навигация (общая для всех списков выбора)

Стиль файлового менеджера: на экране один уровень, сверху хлебные крошки
(`dev / UtkIntegration / User tasks`), снизу строка подсказок.

| Клавиша | Действие |
|---|---|
| `↑ ↓ PgUp PgDn Home End` | движение |
| `Enter` / `→` | войти в пакет / папку |
| `Backspace` / `←` | на уровень вверх |
| `Space` | отметить / снять (на пакете или папке — целиком) |
| печать текста | фильтр по подстроке на текущем уровне; `Esc` — сбросить фильтр |
| `Tab` | переключить вкладку Packages / Files |
| `Ctrl+A` | показать все пакеты / только свои (не `A`: печать букв — это фильтр) |
| `F2` или `Ctrl+S` | перейти к итоговому экрану |
| `Esc` на верхнем уровне | выход (подтверждение, если что-то выбрано) |

Отметки: `[x]` выбрано целиком (зелёный), `[~]` частично (жёлтый), `[ ]` не выбрано (базовый цвет).
Внизу всегда счётчик: `Selected: 12 schemas, 3 files`.

## 2. Export

1. Выбор исходного стенда (список из appsettings; последний использованный — первым).
1a. «What to export?»: **Select** (ручной выбор, ниже) или **Load a list** (добавлено 2026-11-19) — сохранённый список
   (последние / `lists\` / путь) загружается в тот же выбор: секции `package X -> Y:` (элементы по имени, с подсказкой
   типа; маппинг из списка, приоритетнее запомненного), `packages:` (целые пакеты), `files:` (как есть, маски тоже;
   без `Path` у стенда — пропускаются). Чего нет на стенде — показывается списком «Not applied». Затем сразу итоговый
   экран; Back — к ручному выбору с этими отметками. Пакет из секции `package X:` остаётся поэлементным, даже если
   в нём выбраны все элементы (в списке просили не zip-установку); отметка пакета целиком вручную снова делает его целым.
2. Экран выбора с вкладками **Packages** и **Files**. Вкладки Files нет, если у стенда не задан `Path`.
   Отметки на обеих вкладках сохраняются при переключении.

### Вкладка Packages

- По умолчанию — только **свои пакеты**: `InstallType == 0` (не заблокированные) или Maintainer не `Terrasoft`/`Creatio`.
  `Ctrl+A` — все пакеты. Пакет с выбранными элементами виден и в режиме «только свои».
- `Enter` на схеме (не папке) тоже отмечает её; `Esc` на вложенном уровне — на уровень вверх.
- Схемы пакета загружаются при первом входе в пакет и кэшируются до конца сессии.
- Внутри пакета — папки в фиксированном порядке, пустые скрыты, у каждой счётчик `Objects (42)`:

  | Папка | Что попадает |
  |---|---|
  | Objects | EntitySchemaManager (объекты и замещения) |
  | Source code | SourceCodeSchemaManager |
  | Client modules | ClientUnitSchemaManager (JS, страницы Classic и Freedom UI) |
  | User tasks | ProcessUserTaskSchemaManager |
  | Business processes | ProcessSchemaManager |
  | Add-ons | AddonSchemaManager |
  | SQL scripts | SysPackageSQLScript |
  | Data bindings | SysPackageSchemaData |
  | Other | всё остальное (Case/DCM, веб-сервисы, …) — чтобы ничего не терялось молча |

- Внутри папки — схемы по алфавиту. Выбор пакета или папки целиком отмечает все её схемы.
- **Пакет, выбранный целиком** (`[x]`, все элементы), пишется в секцию `packages:` и переносится как в Creatio —
  zip-установщиком (пакет заменяется на цели или создаётся; без маппинга). В списке пакетов у него пометка
  `whole package (zip install)`. Частично выбранный пакет — обычная секция `package X:`.
- Одинаковые имена у объекта и его binding UI разводит сам: в список пишется подсказка `[schema]`/`[data]`/`[sql]`,
  когда имя встречается в пакете больше чем в одной папке.

### Вкладка Files

- Дерево файловой системы относительно корня `Path`, папки сверху, затем файлы, по алфавиту.
- Папка выбрана целиком → одна строка `- path\folder` (рекурсивно; файлы, появившиеся позже, тоже попадут
  в экспорт). На итоговом экране строка помечается `(folder, N files now)`.
- Папка выбрана частично → в список пишутся отдельные файлы и целиком выбранные подпапки.
- Маски (`bin\Utk*.dll`) UI не создаёт; их можно дописать руками в сохранённый список.

### Итоговый экран

- Список в формате cst (секции `package Src -> Target:` и `files:`) — ровно то, что будет сохранено.
- **Referenced but not selected**: схемы из *своих* пакетов, на которые ссылаются выбранные (по GUID в метаданных,
  тот же анализ, что у экспорта; для этого скачиваются zip выбранных пакетов). Запускается **только кнопкой
  Check references** (решение 2026-11-19); пока ссылки не проверены или выбор изменился после проверки (сравнение
  снимка выбора), экран и итоги Save/Export показывают жёлтое предупреждение — не блокируя. Найденные можно
  добавить (Add…). Ссылки на базовые пакеты не показываются. Скачанные пакеты кэшируются на сессию экспорта:
  повторная проверка не качает их снова; Export всегда скачивает заново (архив — текущее состояние стенда) и
  обновляет кэш.
- **Маппинг**: строка `Src -> Target` на каждый исходный пакет; по умолчанию Target = Src или запомненный.
  При правке UI спрашивает целевой стенд (кроме исходного) и показывает список его пакетов с поиском.
  Ручной ввод разрешён; имя, которого нет на стенде, — жёлтым `not found on <env>`. Выбранный целевой стенд
  запоминается и используется в `Import to <env>…`.
- Действия:
  - `Save list…` — по умолчанию `lists\<src>-<yyyyMMdd-HHmm>.txt` рядом с cst, имя можно изменить;
  - `Export archive…` — по умолчанию `archives\<src>-<yyyyMMdd-HHmm>.zip`;
  - `Import to <env>…` — экспорт → дальше поток Import с шага 3 (архив уже выбран, стенд известен);
  - `Back` — вернуться к выбору с сохранёнными отметками;
  - `Quit`.

### Исходный стенд в FSM: загрузка пакетов в БД перед экспортом (2026-11-21)

- При подключении cst спрашивает `WorkspaceExplorerService/GetIsFileDesignMode`; у FSM-стенда в шапке метка `FSM`.
- Перед записью архива (Export, Import из итогов, импорт списка) с FSM-стенда UI спрашивает, загрузить ли пакеты
  экспорта (разделы `package X:` и `packages:`) из файлов в БД. CLI: `export --load-to-db [--allow-delete]`.
  Общая логика — `src\Cst\Transfer\FsmLoader.cs`, вопрос UI — `src\Cst\Ui\FsmPrompt.cs`.
- Зачем: код схем (`.cs`/`.js`/`.less`) экспорт `.md` и так берёт с диска (проверено на dev меткой в файле), а пакет
  целиком (zip `GetZipPackages`), SQL-скрипты, привязки данных, переводы и метаданные идут из БД.
- Загрузка — Creatio `AppInstallerService/LoadPackagesToDB` (как `clio pkg-to-db`), одним вызовом на все пакеты.
  По коду 10.0.0.801: читает весь `Pkg` и всю конфигурацию, пишет элементы, файлы которых отличаются (схемы — MD5
  папки против `SysSchema.Checksum`, SQL и данные — `ModifiedOnUtc`), перезаписывает локальные изменения и
  **удаляет из БД элементы этих пакетов, у которых нет папки на диске**; при `AutoUpdateDBStructure` /
  `AutoInstallSqlScript` / `AutoInstallPackageData` в Web.config ещё обновляет структуру БД, выполняет SQL и ставит
  данные.
- Перед загрузкой cst сравнивает элементы пакетов в БД с папками на диске (нужен `Path`) и показывает, что будет
  удалено и каких пакетов нет на диске. UI: если удалять нечего — первым пунктом «Load into the DB, then export»;
  если что-то удалится или проверить нельзя (нет `Path`) — первым «Export without loading», загрузка только явным
  «Load anyway». CLI в этих случаях останавливается до загрузки (код 2), пока не передан `--allow-delete`.
  Ошибки загрузки — архив не пишется (CLI код 4).
- Проверено на dev: `UtkCstSource` (17 элементов только в БД) — остановка без загрузки; `UtkYachtRental` — загружены
  ровно две страницы с другим хешем, после чего хеши всех 11 схем совпали с диском, повторный запуск — «nothing to
  load». Сценарий `tests\ui-scenarios\fsm-load.keys`.

## 3. Import

1. **Target stand** — из appsettings; рядом виден `DbEngine`. Стенд без `DbEngine` недоступен с пояснением.
2. **Archive** — последние `.zip` из текущей папки, `archives\` и папки cst (новые сверху) + ввод пути.
   Можно выбрать **список `.txt`**: тогда UI спросит исходный стенд и сделает экспорт.
3. **Preview** (`inspect`): таблица — пакеты и маппинг, схемы по типам, SQL, data bindings, файлы.
   Файлы в архиве при отсутствии `Path` у целевого стенда — красным, импорт дальше не пускает.
4. **Data binding check** (`binding-check`), если в архиве есть bindings. Конфликты (тот же Name, другой UId)
   — таблицей; для каждой строки выбор:
   - **Rename** (save as `<name>_resolved`)
   - **Use target UId** (update in place)
   - **Skip**

   Отдельная кнопка **Abort import**. Выбор запекается в resolved-архив (как `binding-check --fix`),
   дальше импортируется он. Keep в UI нет (гарантированно ведёт к падению).
5. **Options**: `No compile` · `Rebuild` · `Data designer` · work dir (по умолчанию как в CLI).
6. **Dry run** — всегда. План по этапам. Код 3 (не хватает зависимостей) → содержимое `.missing.md` на экране,
   импорт не запускается.
7. **Confirm → Import**. Прогресс по этапам: SQL before → schemas → DB structure → compile → SQL after →
   data → files. Компиляция — спиннер с таймером. Подробный вывод — в лог в work dir; `L` показывает хвост лога.
8. **Result**: код выхода человеческими словами, предупреждения, заметки (например, нужен рестарт Creatio
   из-за bin/*.config). При кодах 4 и 5 — кнопка **Restore** из этого work dir.

## 4. Restore

Стенд → папка бэкапа (последние work dir из state + ввод пути) → опция `No compile` → подтверждение →
прогресс → результат (что восстановлено, что нет: выполненный SQL, вставленные строки, новые элементы).

## 5. План реализации

Порядок выбран так, чтобы после каждого шага всё собиралось и CLI работал как раньше.

### Шаг 1. Подготовка ядра (без UI)

- **Log как приёмник.** `Log` сейчас пишет прямо в `Console.Error`, что ломает `Live`-отрисовку Spectre.
  Ввести подменяемый sink (`Log.Sink`), по умолчанию — текущее поведение; UI подставляет sink в файл + буфер
  для `L` и событие этапа для прогресса.
- **Этапы импорта.** В `Importer` — событие/колбэк `Stage(string name)` на границах этапов (п. 3.7).
- **Конфликты bindings.** Вынести интерактивный вопрос из `Cli.PromptBindingFix` за интерфейс
  (`Func<conflict, BindingFix?>`); CLI передаёт текущий `Console.ReadLine`-вариант, UI — таблицу. Логику
  `binding-check --fix` и `WriteResolvedArchive` вынести из `Cli` в отдельный класс, чтобы звать без argv.
- **Запрос пароля.** `AppSettings.Resolve` → колбэк `Func<envName, string?>` для отсутствующего пароля;
  различать 401 и «пользователь заблокирован» в `CreatioClient.LoginAsync` (отдельные исключения).

### Шаг 2. Каталог для выбора
